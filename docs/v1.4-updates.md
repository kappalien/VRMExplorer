# v1.4 一鍵線上更新

設定頁新增「線上更新」，按「一鍵更新」即可檢查正式版、下載與驗證、關閉、替換並重新啟動。若有姿勢草稿，會先提示匯出或捨棄；只有捨棄時才繼續。可啟用「啟動後檢查新版」，此設定不會自動安裝。

新版資訊使用 GitHub 最新正式 Release 的 `update.json`，內含 Ed25519 簽章。程式內建固定公鑰，驗證後才採用版本、平台、下載位置與檔案雜湊。一般 `Update-win-x64.zip` 不包含 WebView2；Runtime 版本不同才額外下載獨立 `Runtime-win-x64.zip`。Runtime 有變動的發行必須用 `--with-runtime` 產出完整的獨立 Runtime 更新包。

Rust 下載在 `data/updates/jobs/`，只允許固定倉庫的 HTTPS 資產與 GitHub 資產轉址，不需 GitHub 帳號或內建 token。取消與下載失敗不改原程式。驗證完整後才啟動獨立 `vrm-updater.exe`，等待主程序退出，再取得資料夾鎖。更新只觸及簽章列出的程式管理檔案，不覆寫 `data/` 或未管理檔案。

替換前保存交易日誌與舊檔備份。新程式成功載入設定並掛載介面後回報健康；60 秒內未回報則終止此次啟動程序、嘗試還原並啟動舊版。斷電／中斷後再次開啟，主程式交給更新器恢復未完成交易。請不要手動刪除 `data/updates/` 中未完成的備份與日誌。舊檔與作業檔暫時保留以供診斷，因此仍需空間容納下載、解壓與備份。

v1.3 以前沒有線上更新功能，需要先以完整 Portable 包或本機 upgrade.ps1 手動升級一次。資料夾須可寫入；開發模式、離線、GitHub 無法連線或資產不齊時會提供明確提示。此階段沒有差分二進位補丁；小包仍含完整 EXE 與必要授權文件。

## 發行者

私鑰位於本機 `build/signing/update-private.pem`，已排除 Git 與發行包並限制 Windows ACL。請另外安全備份；遺失私鑰就無法對現有公鑰簽署後續更新。不可任意重建或輪換公鑰。可用 `VRM_UPDATE_SIGNING_KEY` 指定安全儲存的私鑰檔案。簽章金鑰與 Windows Authenticode 憑證用途不同。

`node scripts/package.mjs` 預設產出小型程式更新包、校驗碼及 `releases/v<版本>/update.json`（上傳資產名稱為 `update.json`）；前提是主程式與獨立更新器已建置。GitHub 完整可攜版只保留 v1.4.1，後續版本只上傳更新資產；使用者另外要求完整包時才加 `--full`。發行時先在 draft Release 上傳所有資產，再公開，避免檢查時抓到不完整的更新。正式發行的 tag、檔名及版本必須一致。Runtime 變動或首次提供跨 Runtime 自動升級時使用 `node scripts/package.mjs --with-runtime`。

## 本階段驗證

- TypeScript、前端建置、ESLint、Rust 編譯／Clippy 與格式檢查通過。
- 前端驗證一鍵串接、取消、姿勢草稿保護及簽章錯誤；Rust 驗證簽章竄改、ZIP 額外項目、檔案損壞、未管理檔案衝突、程序鎖與交易回復。繁中／英文鍵值完整。
- Edge 的四項既有瀏覽、單幀／動畫 VRMA、五萬筆清單及 VRM0 WebGL 檢查通過。
- 實際小型更新包通過內建公鑰簽章、SHA-256 與完整解壓驗證，沒有 data、VRM／VRMA 或 WebView2。
- 獨立 QA 目錄的原生 v1.3 → v1.4 更新、介面健康回報及重新啟動通過；使用立即退出的測試程式驗證新版失敗時還原 v1.3，舊 EXE 雜湊與個人資料保持完整。
- GitHub 正式線上更新、跨 Runtime 更新、實際斷電、磁碟滿、乾淨離線 VM、非管理員及 Windows 10：Not Tested。

首次必須手動取得含更新器的 v1.4 可攜版；後續新版發佈完整簽章資產後才可在線更新。每次發行先上傳完整資產至 draft Release，確認齊全後再公開。
